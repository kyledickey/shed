# AGENTS.md

shed is a self-hosted, single-VPS deployment platform inspired by Railway.
One Go binary serves the dashboard and JSON API, runs the deploy pipeline, and
embeds Caddy as the reverse proxy. Docker runs every workload.

- Projects contain services (no environments). Services are apps (a GitHub
  repo or a Docker image) or databases (Postgres, MySQL, MongoDB, Redis).
- Apps build from their Dockerfile, or with Railpack when there isn't one.
- A single GitHub App handles sign-in, repo access, push webhooks, and CI status.
- State lives in SQLite. Config is TOML (koanf) with `SHED_*` env overrides.
  The app log is `shed.log` next to the config file (lumberjack).

`docs/design.md` is the source of truth for the data model, deploy pipeline,
and the HTTP API contract between Go and the dashboard. Update it in the
same change whenever you change any of these.

## Layout

```
cmd/shed/          entry point: flags, config, logging, wiring, shutdown
internal/config    koanf → Config
internal/store     SQLite, embedded migrations, CRUD on plain structs
internal/docker    Docker Engine wrapper (moby client)
internal/build     clone a commit, build an image (Dockerfile or Railpack)
internal/proxy     embedded Caddy, Apply(routes)
internal/github    GitHub App: manifest, tokens, repos, CI status, OAuth, webhooks
internal/vars      ${{ KEY }} / ${{ service.KEY }} reference resolution
internal/catalog   database templates
internal/s3        S3-compatible object storage client
internal/deploy    deployment pipeline, per-service workers, reconcile on boot
internal/host      host resource usage from procfs, sysfs, and statfs
internal/logtail   in-memory tail of shed's own log
internal/metrics   container and host resource sampling, time series
internal/backup    backups and restores: dumps, archives, zstd, age, schedules, S3
internal/auth      sessions, GitHub sign-in, middleware, OAuth server for agents
internal/control   operations and rules behind every interface (control.Plane)
internal/mcp       read-only MCP server for agents, mounted at /mcp
internal/api       HTTP API, SSE logs, webhook, SPA serving; thin handlers over control
web/               dashboard (Vite+, React, TanStack Router + Query, CSS modules)
web/site/          public site: home page and docs, prerendered to static HTML
deploy/            systemd unit and example config
```

## Architecture: packages are lego pieces

Each package under `internal/` should work as a self-contained piece that
can be understood, tested, and replaced on its own.

- Leaf packages (`config`, `store`, `docker`, `build`, `proxy`, `github`,
  `vars`, `catalog`, `host`, `logtail`, `s3`) import nothing from `internal/`. Keep it that way.
- Interfaces belong to the consumer. A package that needs another's behavior
  declares the small interface it uses (`deploy.Docker`, `auth.Store`, …)
  instead of importing a concrete type. `cmd/shed` wires real
  implementations together, with tiny adapters where needed.
- Pass dependencies in explicitly: no package-level state, no `init` side
  effects, no global loggers. The only exception is Caddy's process-global
  state, which stays contained in `internal/proxy`.
- Keep APIs narrow. Export only what callers need. Prefer plain structs and
  functions over frameworks and abstractions.
- New functionality goes in the package that owns it, or in a new leaf
  package if it's a separable concern. Don't create grab-bag `util` packages.

## Go style

Follow the [Google Go style guide](https://google.github.io/styleguide/go/)
and [Go doc comments](https://go.dev/doc/comment).

- Every package has a package comment. Every exported identifier has a doc
  comment that starts with its name and reads as a complete sentence.
- Use clear names without stutter (`store.Open`, not `store.OpenStore`). Keep
  receiver names short and consistent.
- Wrap errors with context: `fmt.Errorf("build: clone %s: %w", repo, err)`.
  Return errors instead of logging and continuing. Use sentinel errors
  (`store.ErrNotFound`) for conditions callers branch on.
- `context.Context` is the first parameter of anything that does I/O.
- Log with `log/slog`, using a logger that was passed in.
- Write table-driven tests for logic and fakes for interfaces. Tests must not
  need a Docker daemon or network unless they're clearly marked integration
  tests.
- Code must pass `gofmt`, `go vet`, and `go test -race`. Avoid speculative
  features, dead code, and comments that restate the code.

## Dashboard

- React + TypeScript (strict), TanStack Router (file-based, `src/routes/`),
  TanStack Query (hooks in `src/api/`), CSS Modules with design tokens in
  `src/styles/`. Don't use Tailwind or CSS-in-JS.
- `src/api/types.ts` mirrors the types in `docs/design.md`. Change both
  together.
- `bun run build` writes `web/dist`, which the Go binary embeds through
  `web/embed.go`. `src/routeTree.gen.ts` is generated by the router plugin,
  and it is committed.

## In-app docs

The dashboard's `/docs` pages are MDX files in `web/src/features/docs/content/`.
The public site (`web/site/`) serves the same pages.
Each page is one `<slug>.mdx` with frontmatter (`title`, `group`, `order`,
`description`); its `##` headings become the sidebar sections and anchor ids.

- Write Markdown. Use JSX only for components: shared ones are available
  everywhere (see `mdx.tsx`), page-specific diagrams and demos live in
  `components/<slug>/` and are imported at the top of the page.
- Operator pages describe behavior, paths, config keys, endpoints, and
  limits; Go packages and functions belong in the "Developing" group.
- `?` tooltips in the dashboard are entries in `topics.ts`. `docs.test.ts`
  fails if a tooltip or a `/docs/...#id` link points at a heading that no
  longer exists, so run the tests after renaming a heading.

Update the docs in the same change whenever you change anything relevant.

## Commands

```sh
make build                      # dashboard + bin/shed
make test                       # go test
go vet ./...
cd web && bun install           # first time
cd web && bun run dev           # dashboard dev server, proxies /api to :3000
cd web && bun run site:dev      # public site dev server
make site                       # prerender the public site to web/site-dist/client
cd web && bunx vp check          # format, lint, typecheck
```

Runtime requirements: Linux, Docker with buildx, `git`, and `railpack`.

## Commits

Use short, standard commit messages with little or no body. Don't add
co-author or attribution trailers. Work on a branch, not `main`.
