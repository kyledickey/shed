1Runtime: what's running on the box

Everything in the green dashed box is the single shed process. Traffic enters through Caddy, which runs inside shed: shed owns the routing table and pushes it to Caddy whenever a deployment goes live.

2Packages: lego pieces

The Go code is split so each piece can be understood and tested alone. Arrows point from the importer to what it imports. The bottom row are leaf packages: they import nothing from internal/.

Interfaces belong to the consumer. deploy doesn't depend on the concrete Docker client; it declares a small deploy.Docker interface with just the methods it calls. cmd/shed plugs in the real implementation. Tests plug in a fake, so nothing needs a Docker daemon to run go test. (Where an upper package imports a leaf, it's mostly for plain struct types like store.Service.) Similarly, the backup → S3 link is an interface wired up in cmd/shed, not an import.

3From git push to live

Each service has one worker goroutine. A newer deployment cancels older unfinished ones for the same service, so rapid pushes don't pile up.

On boot: reconcile

If shed (or the VPS) restarts mid-deploy, deploy.Reconcile marks orphaned in-progress deployments failed, makes sure every non-stopped service's active container is running (recreating it from the saved runtime snapshot if needed), removes stray containers, and re-applies proxy routes. Pushes that arrived but weren't deployed are replayed.

4The zero-downtime switch

The trick is that the new container starts without the service's network name. It only takes over the name (and public routes) once it's proven healthy.

5Networking & variables

Each project is its own Docker network. Inside it, a service is reachable at <service name>:<port>. That's the "private domain". Variables can reference each other, so apps never hard-code another service's credentials.

6Backups

Every service with a volume, plus shed's own database, can be backed up on a cron schedule. A backup is one ordinary file you could restore by hand with standard tools.

Restores load the archive back in. While a restore is changing a service's data, a restore fence blocks deploys and pushes for that service so nothing starts on half-restored data.

7Data model

All state is in one SQLite file. The core shape is small:

Deployment statuses: queued → waiting / building / deploying → active, or failed, skipped, canceled. A superseded deployment becomes removed; an active one whose container died shows as crashed.

8Design choices (and why)

ChoiceWhyTrade-off
Single Go binaryOne thing to install, upgrade, and run under systemd. Dashboard is embedded with go:embed.Not horizontally scalable, by design: it's for one VPS.
Embedded CaddyAutomatic HTTPS for free, and shed controls routes in-process with proxy.Apply(routes), with no config files or second daemon to sync.Caddy has process-global state; it's quarantined in internal/proxy.
Docker for everythingApps and databases are uniform: same lifecycle, logs, metrics, networks, volumes.Needs Docker + buildx on the host.
Dockerfile, else RailpackRespect a repo's own Dockerfile; otherwise build with zero config like Railway does.railpack must be on PATH.
One GitHub AppOne setup flow (manifest) covers sign-in, private repo cloning, push webhooks, and CI checks. Credentials stored in SQLite.GitHub is required, even for sign-in.
No environmentsKeeps the model tiny: project → services. Want staging? Make another project.No per-env variable overrides.
SQLiteZero ops, one file, easy to back up (shed backs itself up with VACUUM INTO).Single writer, which is fine at this scale.
Per-project Docker networkServices talk by name (postgres:5432) and projects are isolated from each other.—
Start new, then switchZero-downtime deploys: the old container keeps serving until the new one passes health checks twice.Volume-backed services must stop first (brief gap).
Runtime snapshot on deployThe active deployment remembers its exact command, resolved vars, limits, and volumes, so reboots and restarts recreate it faithfully.Edited settings wait for the next deploy.
Standard backup formatszstd + age + plain SQL/tar means you can recover without shed.—
Consumer-owned interfacesPackages are swappable and testable with fakes; tests never need Docker or network.A bit of adapter code in cmd/shed.
Explicit allowlistOnly GitHub logins in auth.allowed_users can sign in; empty list = nobody.Revoking someone means editing config and restarting.
